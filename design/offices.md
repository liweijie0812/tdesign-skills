# TDesign Offices Web 中后台设计指南

来源：TDesign 官网 `https://tdesign.tencent.com/design/offices`，上游源码 `Tencent/tdesign/docs/design/offices_zh-CN.md`。

当用户询问 Web 中后台设计、后台框架、后台页面模板、整站导航、区域导航、上下/左右/混合布局，或要求搭建桌面端管理后台页面时，先按本文判断页面框架，再结合 `design/layout.md`、`design/offices-task.md`、`scenarios/` 和当前技术栈 API 实现。Mobile / Miniprogram 不照搬本文的桌面后台框架，只参考任务拆分思路并回到对应端组件。

## 核心规则

- 本文适用于 Web 中后台和桌面浏览器管理系统，不作为 Mobile / Miniprogram 后台页面框架规范。
- 中台与后台在 Web 前端设计中具有同质性，可按同一类中后台系统思考设计方法。
- 快速搭建好用的中后台系统通常分三步：选择合适的页面框架、设计页面间任务流程、合理使用组件。
- 页面框架由页面导航与页面布局组成；页面布局由栅格和布局能力组成。
- 布局选择主要看功能模块数量，以及功能之间的相关性。
- TDesign 提供常见中后台页面模板；生成页面前先判断页面类型，不要从空白 `div` 开始堆布局。

## 导航分类

| 导航类型 | 定义 | 相关组件 |
| --- | --- | --- |
| 整站导航 | 对整个网站系统最大颗粒度模块的引导，也称全局导航或总导航 | `Menu` |
| 区域导航 | 对某一模块下页面进行引导和分类，也称情景导航 | `Affix`、`Anchor`、`Breadcrumb`、`Dropdown`、`Pagination`、`Steps`、`Tabs` |

使用建议：

- 整站导航用于一级模块，例如概览、订单、商品、用户、系统设置。
- 区域导航用于模块内定位、流程切换、页内锚点、分页和上下文操作。
- 面包屑表达当前位置，不替代主导航。
- 步骤条表达任务进度，不替代模块导航。

## 页面布局选择

TDesign 中后台主要提供 3 种布局方式：上下布局、左右布局、混合布局。

| 布局 | 主要特征 | 何时使用 | 注意 |
| --- | --- | --- | --- |
| 上下结构 | 导航在上，信息内容在下；横向导航空间有限，左右点击效率低 | 功能模块数量较少，一般少于 `9` 个；模块关联较弱、需要明确区分或无需频繁切换 | 内容区常需要稳定宽度，避免顶部导航过长 |
| 左右结构 | 导航在左，信息内容在右；纵向空间延展性好，上下点击效率高 | 功能模块较多；模块有一定相关性，或需要频繁切换 | 需要考虑侧边栏展开/收起和内容区宽度 |
| 混合结构 | 上下与左右结合；横纵空间优势互补 | 功能模块较多；模块有父子或交叉关系，需要按层级展示 | 适合复杂应用型网站，但不要让顶部和侧边重复承载同一层级 |

实现建议：

- Web 应用壳优先用 `Layout`、`Header`、`Aside`、`Content`、`Footer`。
- 导航优先用 `Menu`，模块内导航按场景选 `Tabs`、`Breadcrumb`、`Anchor`、`Steps`。
- 栅格、断点、间距和侧边栏宽度规则查 `design/layout.md`。
- 若项目已有 TDesign Starter 页面模板，优先沿用模板结构和导航约定。

| 页面模板 | 常见高频任务 |
| --- | --- |
| 仪表盘 | 数据筛选与查询、效果预览、新手指引 |
| 列表页 | 数据筛选与查询、表格批量操作、数据导入、效果预览、状态流转、任务引导、新手指引 |
| 表单页 | 数据筛选与查询、任务引导、效果预览、新手指引 |
| 详情页 | 数据筛选与查询、状态流转、数据导入、效果预览 |
| 结果页 | 状态流转、新手指引、任务引导 |
| 个人页 | 新手指引、效果预览 |
| 登录页 | 新手指引、任务引导 |

## 搭建流程

1. 明确系统信息架构：一级模块、二级模块、页面数量、模块相关性。
2. 选择导航类型：整站导航用 `Menu`，区域导航按页内任务选择合适组件。
3. 选择布局：少模块弱关联用上下结构，多模块频繁切换用左右结构，复杂层级用混合结构。
4. 匹配页面模板：仪表盘、列表页、表单页、详情页、结果页、个人页或登录页。
5. 识别高频任务：筛选查询、批量操作、导入、状态流转、任务引导、效果预览、新手指引。
6. 查 `design/offices-task.md` 选择任务流程，再查当前技术栈组件 API。

## 禁止行为

- 禁止不分析模块数量和层级关系，默认所有后台都使用同一种导航布局。
- 禁止用面包屑、步骤条或 Tabs 替代整站主导航。
- 禁止功能模块很多时强行使用顶部横向导航，导致导航拥挤和切换效率低。
- 禁止把 Web 中后台的整站导航、左右结构或混合结构直接套到 Mobile / Miniprogram。
- 禁止在页面模板已有 TDesign 组件能力时，用自定义布局和自研组件重做后台框架。
- 禁止只搭页面静态结构，不设计页面间的任务流程。
