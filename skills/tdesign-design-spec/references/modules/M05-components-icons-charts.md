# M05 - Components / Icons / Charts

本模块定义无设计文件场景下的 TDesign 组件、图标和图表规则。它接收 `M01` 的真实组件、真图表、图标来源和 Web 图标渲染红线，接收 `M02` 的颜色语义与对比规则，并接收 `M03` 的尺寸与间距规则。

## 1. 使用优先级

1. 业务模块优先使用真实 TDesign 组件或项目已有等价封装，不用图标、截图、静态块、裸 `div` 或无语义容器伪装组件。
2. 组件外观优先使用 `theme`、`status`、`variant`、`size`、`layout`、`loading`、`disabled` 等公开 API，不优先覆盖内部 class。
3. 具体 props、事件、插槽、导入方式和组件覆盖范围必须回到当前技术栈 API 或项目依赖确认，不凭组件名猜写法。
4. 组件颜色、图标颜色、有色实心底前景按 `M02` 语义 Token 执行；组件尺寸、图标间距和圆角按 `M03` 执行。
5. 当前栈缺少某组件时，优先使用同栈 TDesign 相近组件或项目已有封装；再考虑最小原生能力，并说明降级原因。

## 2. 业务组件与图标资源区分

业务组件用于承载交互、状态和数据结构；图标只用于表达辅助语义。

| 类型 | 正确用途 | 禁止用途 |
| --- | --- | --- |
| `Table` | 结构化行列数据、排序、筛选、选择、操作列 | 用表格图标、截图或静态块替代 |
| `Form` / `FormItem` | 查询、录入、校验、配置表单 | 用普通容器拼字段和错误态 |
| `Button` / `Link` | 主次操作、危险操作入口 | 用纯文本或图标假装按钮 |
| `Tag` / `Badge` | 状态、分类、计数提示 | 只用颜色块无文字表达状态 |
| `Breadcrumb` / `Tabs` / `Steps` | 位置、分组、流程进度 | 用图标或静态文字代替导航语义 |
| `Dialog` / `Drawer` / `Popconfirm` | 临时任务、详情、危险操作确认 | 手写弹层或只改按钮颜色 |
| `Empty` / `Loading` / `Skeleton` / `Alert` | 空态、加载、错误、说明 | 留空白或用无语义插图代替 |

禁止把任何图标资源当成整块业务组件使用，例如用 `table-filled`、`table-2` 或表格图标代替真实 `Table`，用按钮图标代替真实 `Button`，用标签图标代替真实 `Tag`。

## 3. 组件变体选择策略

### 操作类组件

- 主操作：使用 TDesign 主按钮 / primary 语义，一页保持一个主要主操作。
- 次要操作：使用普通按钮、文本按钮、链接或 `Dropdown` 承载。
- 危险操作：使用 danger / error 语义，并配合 `Popconfirm`、`Dialog` 或当前栈等价确认组件。
- 异步操作：必须提供 `loading`、禁用或防重复提交策略。

### 状态类组件

- 成功、告警、错误、禁用和加载状态必须同时有文案、组件状态、图标或反馈，不只依赖颜色。
- `Tag`、`Badge`、`Alert`、`Message` 等状态组件优先使用 `theme` / `status` 等语义 props。
- 自定义彩色实心底必须使用 `color: var(--td-text-color-anti)`，详见 `M02`。

### 容器与布局组件

- Web 中后台页面优先使用 `Layout`、`Header`、`Aside`、`Content`、`Card`、`Space`、`Row`、`Col` 组织结构。
- Mobile / Miniprogram 不照搬 Web 应用壳；优先使用当前端 `Navbar`、`TabBar`、`Cell`、`Grid`、`List`、`Popup` 等能力。
- 只有组件组合无法表达时，才补最小业务 CSS。

## 4. Table 规则

结构化行列数据必须使用真实 `Table` 与列配置实现。

### 必须覆盖

- 列配置：字段、标题、宽度、对齐、固定列、操作列按业务需要明确。
- 数据状态：加载、空数据、失败、无权限或无结果状态必须可见。
- 数据交互：排序、筛选、选择、展开、编辑、分页按场景启用，不用静态表格截图。
- 操作列：只放高频动作，低频动作折叠到 `Dropdown` 或更多操作。
- 危险操作：删除、禁用、下线、清空等必须有二次确认。

### 禁止

- 禁止用 `table-filled`、表格图标、截图、静态块或卡片拼接伪装 `Table`。
- 禁止用裸 `div` / `ul` 手写完整表格交互、分页和状态。
- 禁止表格只有视觉结构，没有排序、选择、空态、加载态或错误态等必要交互状态。

## 5. 图标规则

### 来源与渲染

所有常规 UI 图标必须来自 TDesign Icons，并使用当前技术栈官方图标组件渲染。

| 技术栈 | 推荐写法 |
| --- | --- |
| Vue | `<t-icon name="..." />` 或当前栈官方按需图标组件 |
| React | `<Icon name="..." />` 或 `tdesign-icons-react` 官方组件 |

图标 `name` 必须先查权威清单，清单未收录不得自造：`https://github.com/Tencent/tdesign-icons/blob/develop/packages/view/src/manifest.js`。

### 适用位置

- 导航图标。
- 按钮前缀 / 后缀图标。
- 状态提示和反馈图标。
- 列表项、操作入口和空状态图标。
- 表格操作列和更多操作入口。

### 禁止

- Emoji 作为 UI 图标，例如 `🚀`、`✅`、`⚠️`、`🔥`。
- 自定义 SVG / path。
- PNG、JPG、截图或临时网络图片。
- 外部 iconfont 或第二套图标库。
- 未查 manifest 自造图标 `name`。

### 尺寸与颜色

图标默认继承上下文文本颜色。必要时使用语义 Token：

```css
.action-icon {
  color: var(--td-text-color-secondary);
}

.primary-icon {
  color: var(--td-brand-color);
}
```

禁止硬编码图标颜色，例如 `#333`、`#666`、`#0052d9`。彩色实心底上的图标必须使用 `--td-text-color-anti`。

### CDN 接入

生成独立 HTML / CDN 示例时，除 TDesign UI CSS / JS 外，必须同时引入对应框架的 TDesign Icons 包，例如 Vue 3 使用 `tdesign-icons-vue-next`。未引入图标包时，不得用 Emoji、自绘 SVG 或外部图片兜底。

## 6. 图表规则

凡需要表达趋势、对比、分布、关系、转化或占比的模块，必须使用项目已有图表库、TVision Charts 或明确的图表组件。禁止用占位框、纯矢量、自绘装饰块、截图、静态块或无关图标冒充图表。

### 必须覆盖

- 图表标题、时间范围、单位、图例和数据更新时间。
- 加载、空数据、失败、无权限或无数据权限状态。
- 筛选区、下钻入口、数据明细或导出入口按业务需要提供。
- 坐标轴、说明文字和辅助标签使用次要语义色或图表库主题，不滥用功能色。
- 数据序列使用项目图表规范、TVision 色板或明确图表主题；成功、告警、错误等功能色只表达对应业务语义。

### 禁止

- 禁止空白卡片写“图表占位”。
- 禁止用无关图标、插图或装饰色块替代真实图表。
- 禁止用功能色随意表示多分类数据，导致成功 / 告警 / 错误语义混乱。
- 禁止只展示静态图片而缺少加载、空态、失败态和数据说明。

## 7. 生成与审计检查

- 页面骨架、表单、表格、分页、弹层、反馈和导航是否使用真实 TDesign 组件。
- 结构化行列数据是否使用真实 `Table` 和列配置。
- 图标是否来自 TDesign Icons，且 `name` 已按 manifest 校验。
- Web 图标是否用 `<t-icon>`、`Icon` 或当前技术栈官方图标组件渲染。
- 图标、状态和有色实心底前景是否绑定 `M02` 语义 Token。
- 图表是否使用真实图表库 / 图表组件，并覆盖加载、空态和失败态。
- 危险操作是否使用确认组件，异步操作是否有 loading 或禁用策略。
- 是否存在图标、截图、静态块或裸 DOM 伪装业务组件的情况。
