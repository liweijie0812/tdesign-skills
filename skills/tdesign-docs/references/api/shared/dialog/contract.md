# Dialog 通用契约

本文件描述跨 Web、移动端、小程序和 uni-app 都成立的 Dialog 语义。它不是 API 权威来源；具体 props、事件名、插槽、函数式调用和类型必须回到当前端与当前栈 API 文档确认。

## 端差异入口

- Web：见 [dialog/web.md](./web.md)，覆盖 React、Vue Next 和 Vue 2。
- 移动端：见 [dialog/mobile.md](./mobile.md)，覆盖 Mobile React 和 Mobile Vue。
- 小程序 / uni-app：见 [dialog/miniprogram.md](./miniprogram.md)，覆盖 `tdesign-miniprogram` 和 `tdesign-uniapp` 的平台差异入口。

## 适用场景

- 局部中断当前任务，让用户完成确认、告警、短表单或关键决策。
- 展示需要聚焦处理的信息，并提供明确的确认、取消或关闭路径。
- 对破坏性或高后果操作进行强确认。
- 用于需要短时间聚焦处理的内容，不用于承载长期浏览、复杂筛选或多步骤配置。
- 函数式创建适合即时确认、提示和告警；常驻组件适合由页面状态控制的业务弹窗。

## 不适用场景

- 内容需要大量横向或纵向空间时，优先考虑 `Drawer`、页面内区域或独立页面。
- 操作只是轻量二次确认时，优先考虑 `Popconfirm`，不要把简单确认都升级成阻断弹窗。
- 仅展示操作结果时，优先考虑 `Message`、`Toast` 或 `Notification`，不要让用户多点一次关闭。
- 需要持续对照主页面内容时，优先考虑 `Drawer` 或页面内编辑区。

## 内容语义

- 标题区表达对话框目的，不要只写“提示”。
- 内容区放说明、表单或需要用户确认的关键信息。
- 操作区放主要操作和次要操作，按钮文案应表达结果。
- 关闭按钮、遮罩关闭、ESC 关闭或返回关闭是否启用，应按业务后果决定。
- 破坏性操作的确认按钮要表达结果，例如“删除项目”“停用账号”，不要只写“确定”。
- 弹窗内表单应短小且目标明确；超过少量关键字段时优先改用 `Drawer` 或页面。

## 状态语义

- 展示状态应受业务状态驱动，常见语义是 `visible`。
- 确认动作处理中应避免重复提交；是否有确认 loading、实例方法或异步关闭钩子，要按当前端 API 确认。
- 关闭后是否销毁子内容会影响表单状态保留；是否支持销毁配置，要按当前端 API 确认。
- 遮罩、滚动穿透和层级配置影响浮层体验，默认值不同端不能互抄。
- 受控关闭要区分“用户触发关闭”和“业务允许关闭”；需要异步校验时优先使用当前栈支持的关闭拦截或在确认回调中控制状态。
- 函数式实例通常需要显式销毁或更新，避免路由切换后遗留浮层。

## 事件语义

- 确认事件表示用户触发主要确认动作，不等于一定提交成功。
- 取消事件表示用户触发取消按钮，通常也会触发关闭链路。
- 关闭事件表示对话框正在关闭，触发来源可能是取消、关闭按钮、遮罩、ESC 或平台返回行为。
- 动画生命周期事件并非所有端都完整支持，使用前查当前端 API。
- 遮罩点击事件和关闭事件不是同一语义；只需要埋点遮罩点击时不要替代关闭处理。
- 关闭来源类型在不同端不同，不能把 Web 的 `esc`、移动端的 `overlay`、小程序的触发源或 uni-app 的 `@event` 参数互相套用。

## 交互约束

- 高风险操作默认不建议开启遮罩关闭、ESC 关闭或平台返回直接关闭，除非有明确的撤销或保存策略。
- 主要操作放在视觉和交互上更明确的位置，次要操作不能比破坏性确认更突出。
- 弹窗出现后应让用户能理解当前任务、后果和可选路径，不用纯图标或含糊文案承担关键决策。
- 避免弹窗套弹窗；需要连续步骤时改成流程页、抽屉或明确的分步组件。
