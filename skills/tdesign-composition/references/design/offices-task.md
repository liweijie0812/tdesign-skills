# TDesign Offices Task Web 中后台高频任务设计方法

来源：TDesign 官网 `https://tdesign.tencent.com/design/offices-task`，上游源码 `Tencent/tdesign/docs/design/offices-task_zh-CN.md`。

当用户询问 Web 中后台任务流程、筛选查询、表格批量操作、数据导入、状态流转、任务引导、效果预览、新手指引，或要求生成桌面端后台列表页、表单页、详情页等任务型页面时，先按本文选择任务模式，再查当前技术栈组件 API。Mobile / Miniprogram 可参考任务拆分，但交互密度、导航、表格和反馈组件必须按对应端 API 重新选型。

## 核心规则

- 本文适用于 Web 中后台高频任务，不作为 Mobile / Miniprogram 交互布局规范。
- 中后台产品虽服务不同业务，但高频任务高度同质化；优先复用成熟任务模式。
- 明确整体框架和页面布局后，再根据业务场景设计任务流程。
- 每个任务都应明确：何时使用、核心流程、相关组件和反馈方式。
- 任务流程要围绕用户目标，不要只按数据字段堆表单和表格。
- 任务页面中的颜色、文字、边框、背景、间距和圆角优先使用 TDesign 语义 Token，不写零散硬编码值。
- 表格、表单、弹窗、步骤、分页、上传、反馈和图标必须优先使用 TDesign 真实组件；禁止用图标、截图、静态块或无语义容器冒充组件。
- 图标必须先通过 `tdesign-icons` manifest 查询确认名称，禁止 Emoji、自绘 SVG、外部 iconfont 或临时网络图片占位。
- 任务状态必须覆盖开始、执行中、成功、失败、空数据、无权限和可恢复路径；状态表达不要只依赖颜色。
- 组件 API 必须回到当前技术栈确认；本文只给任务模式和组件选型方向。

## 数据筛选与查询

按条件或类型选择数据项，或查询数据结果。常用于仪表盘、列表页。

| 模式 | 何时使用 | 核心流程 | 相关组件 |
| --- | --- | --- | --- |
| 查询后生效 | 用户对查询范围有明确针对性，需要一系列筛选过滤后一次性提交 | 选择条件 -> 触发查询 -> 获得结果数据 -> 清空条件 | `TimePicker`、`DatePicker`、`Input`、`Select`、`Button`、`Table` |
| 立即生效 | 查询范围较随机，用户需要反复多次修改条件 | 条件选择 -> 获得结果数据 -> 条件修改 -> 获得结果数据 | `TimePicker`、`DatePicker`、`Input`、`Select`、`Button`、`Table` |
| 折叠条件 | 筛选项过多，全部展示会增加识别成本 | 展开条件 -> 条件选择 -> 获得结果数据 | `Form`、`Button`、`Table`，配合折叠/展开能力 |
| 条件模板保存与调用 | 筛选需求个性化强，需要保存和复用筛选项 | 条件选择 -> 保存为模板 -> 模板调用 | `Input`、`Select`、`Button`、`Table`，必要时用 `Dialog` |

实现建议：

- 明确查询后生效还是立即生效；不要混用导致用户不知道何时刷新结果。
- 高频筛选项外露，低频筛选项折叠。
- 查询按钮、重置按钮、结果反馈和空状态要完整。

## 表格批量操作

对报表中的多项数据进行统一操作。常用于列表页。

| 模式 | 何时使用 | 核心流程 | 相关组件 |
| --- | --- | --- | --- |
| 所见即所得 | 批量操作按钮是主要或高频操作，无论是否选择数据都需要给用户操作预期 | 选择要操作的内容 -> 进行操作 -> 显示操作结果 | `Table`、`Button`、`Checkbox`、`Dropdown`、`Message` |
| 选择后触发 | 页面已有主要按钮，批量操作是次级或非高频操作 | 选择要操作的内容 -> 进行操作 -> 显示操作结果 | `Table`、`Checkbox`、`Dropdown`、`Input`、`Select`、`Button` |

实现建议：

- 批量操作必须依赖表格选择状态，明确已选数量。
- 高风险批量操作需要二次确认，优先 `Popconfirm` 或 `Dialog`。
- 操作完成后给 `Message` / `Notification` 反馈，并刷新或更新表格数据。

## 效果预览

编辑或改变的数据未最终生效前，让用户提前了解效果。常用于仪表盘、结果页、详情页。

| 模式 | 何时使用 | 核心流程 | 相关组件 |
| --- | --- | --- | --- |
| 异步触发 | 配置项较多，或实时刷新有延迟，需要集中预览效果 | 填写表单/配置项 -> 点击预览 -> 进行预览 | `Form`、`Button`、`Input`、`Upload`、`Dropdown`、`Radio`、`Checkbox`、`Select` |
| 同步预览 | 配置过程中需要实时关注最终效果或观察配置变化 | 填写表单/设置项 -> 进行预览 | `Form`、`Input`、`Radio`、`Checkbox`、`Select` |

实现建议：

- 预览不等于提交，必须区分预览、保存、发布等动作。
- 同步预览适合局部、轻量、低延迟场景；异步预览适合复杂或耗时场景。
- 需要趋势、对比、分布、关系、转化等图表化预览时，优先接入项目已有图表库或明确图表组件；禁止用占位框、无关图标或纯静态装饰块冒充图表。
- 预览区的加载、空状态、错误状态和说明文字仍使用 TDesign 组件与语义 Token 组织。

## 新手指引

为新用户提供功能介绍或使用说明。可出现在任意页面。

| 模式 | 何时使用 | 核心流程 | 相关组件 |
| --- | --- | --- | --- |
| 阻断式指引 | 用户必须阅读，或指引过程中不建议操作其他内容 | 触发引导 -> 逐步查看引导 -> 结束引导 | `Dialog` |
| 非阻断式引导 | 指引内容为辅助说明，用户可边操作边查看 | 触发引导 -> 查看或忽视引导继续操作 -> 结束引导 | `Popconfirm`、`Popup`、`Tooltip` |
| 主动触发引导 | 指引内容较多，或用户需要反复查看 | 触发引导 -> 选择任务 -> 进入引导 -> 逐步查看 -> 结束 | `Popconfirm`、`Popup`、`Tooltip`、`Dialog` |

实现建议：

- 关键必读用阻断式，普通说明用非阻断式。
- 不要把关键业务信息只放在 `Tooltip` 中。
- 支持跳过、关闭或再次查看，避免长期打断用户。

## 数据导入

将本地数据导入中后台系统。常用于列表页。

| 模式 | 何时使用 | 核心流程 | 相关组件 |
| --- | --- | --- | --- |
| 逐个文件导入 | 需要轻量快速导入并显示结果，或待导入格式较集中 | 触发导入 -> 选择一个文件 -> 开始导入 -> 收到导入结果 | `Button`、`Upload`、`Message`、`Table`、`List`、`Tooltip` |
| 批量文件导入 | 待导入数据较复杂，或数据文件有多个 | 触发导入 -> 选择上传方式 -> 批量上传 -> 确认上传结果 -> 导入文件 | `Button`、`Upload`、`Message`、`Table`、`List`、`Dialog` |

实现建议：

- 导入前说明文件格式、大小、字段要求和示例模板。
- 导入中展示进度，导入后展示成功、失败和错误详情。
- 批量导入需要确认步骤，避免误导入。
- 上传入口、进度、结果列表和错误详情使用 `Upload`、`Table`、`List`、`Dialog`、`Message` 等真实组件，不用静态块模拟导入流程。

## 状态流转

对某条数据项的状态进行调整或变化。常用于列表页、详情页、结果页。

| 模式 | 何时使用 | 核心流程 | 相关组件 |
| --- | --- | --- | --- |
| 通过详情流转 | 单条信息内容较多或较复杂，需要查看详情后再决策 | 列表选定数据项 -> 查看详情 -> 选择状态 -> 确定流转 -> 显示结果 | `Steps`、`Table`、`Form`、`Dropdown`、`Button` |
| 通过列表摘要流转 | 单条信息较少，通过标题或摘要即可判断，无需校验详情 | 列表选定数据项 -> 选择状态 -> 显示结果 | `List`、`Table`、`Dropdown`、`Button` |

实现建议：

- 状态流转必须清楚展示当前状态、可选下一状态和结果反馈。
- 高风险流转需要二次确认和失败兜底。
- 多步骤状态流转优先使用 `Steps` 表达进度。

## 任务引导

用户需要完成某个任务或使用某项功能时，提供必要指导或说明。常用于详情页、结果页。

| 模式 | 何时使用 | 核心流程 | 相关组件 |
| --- | --- | --- | --- |
| 任务开始前引导 | 任务较复杂，或执行前需要做必要准备 | 查看引导内容 -> 按引导执行任务 | `Tooltip`、`Dialog`、`Steps`、`Card`、`Button` |
| 任务结束后引导 | 任务结果与另一任务相关，或完成后会触发后续操作 | 执行任务 -> 查看结果引导 -> 选择是否执行下一任务 | `Tooltip`、`Dialog`、`Steps`、`Card`、`Button` |

实现建议：

- 开始前引导强调准备事项、风险和路径。
- 结束后引导强调下一步动作、结果解释和可恢复路径。
- 引导内容不要替代真实表单校验、权限校验或错误反馈。

## 页面任务速查

| 页面 | 优先考虑的高频任务 |
| --- | --- |
| 仪表盘 | 数据筛选与查询、效果预览、新手指引 |
| 列表页 | 数据筛选与查询、表格批量操作、数据导入、状态流转、任务引导、新手指引 |
| 表单页 | 任务引导、效果预览、新手指引 |
| 详情页 | 状态流转、数据导入、效果预览、任务引导 |
| 结果页 | 状态流转、新手指引、任务引导 |

## 禁止行为

- 禁止只生成字段和按钮，不设计任务开始、执行、反馈和结束状态。
- 禁止把 Web 后台高密度表格、批量工具栏和桌面弹层反馈直接套到 Mobile / Miniprogram。
- 禁止把查询后生效和立即生效混在同一筛选区域且无明确提示。
- 禁止批量操作不展示已选数量或无结果反馈。
- 禁止用图标、截图或静态块替代真实 `Table`、`Form`、`Upload`、`Dialog`、`Steps`、`Pagination` 和反馈组件。
- 禁止图表、效果预览或趋势分析只放占位框、无关图标或装饰色块。
- 禁止任务状态色跨语义使用，例如成功、告警、错误互相替代。
- 禁止导入任务缺少格式说明、错误详情和导入结果。
- 禁止状态流转缺少当前状态、下一状态和确认反馈。
