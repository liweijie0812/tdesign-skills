# TDesign Web 中后台 Layout 布局

来源：TDesign 官网 `https://tdesign.tencent.com/design/layout`，上游源码 `Tencent/tdesign/site/src/pages/design/layout_zh-CN.vue`。

当用户询问 Web 中后台布局、导航布局、应用壳、栅格系统、响应式布局、断点、间距、侧边栏宽度或页面框架时，先按本文判断设计规则，再按当前技术栈查 `Layout`、`Grid`、`Row`、`Col`、`Menu` 等组件 API。Mobile / Miniprogram 只参考栅格和间距原则，页面结构必须回到对应端场景卡和 API。

## 核心规则

- 本文主规则适用于 Web 中后台和桌面浏览器应用壳，不作为 Mobile / Miniprogram 页面框架规范。
- 布局是 Web 中后台页面统一交互和视觉风格的基础，优先用 TDesign 布局组件组织页面，不要手写大量 `div` 和 CSS 复刻。
- Web 设计团队标准画板宽度为 `1440px` 或 `1920px`。
- 布局区域包含 `Content`、`Header`、`Aside`、`Footer` 4 类。
- TDesign 栅格基数为 `8px`；间距遵循 8 倍数原则，并补充 `4px`、`12px` 两档小间距。
- Web 内容区域采用 `12` 栅格系统，在栅格中放置内容区块时应从列开始，到列结束。
- `Header` / `Aside` / `Content` / `Footer`、侧边栏宽度和桌面断点只按 Web 中后台理解；Mobile 和 Miniprogram 主要使用 `Row` / `Col` 栅格，不等同 Web 应用壳 `Layout`。

## Web 布局区域

| 区域 | 位置 | 典型内容 |
| --- | --- | --- |
| `Content` | 主体内容区 | 页面主要信息、表单、表格、详情、卡片 |
| `Header` | 页面顶部 | 顶部导航、全局操作、品牌信息 |
| `Aside` | 主体内容两侧 | 侧边导航、分组菜单、辅助导航 |
| `Footer` | 页面底部 | 辅助信息、版权、次要链接 |

## 导航布局分类

| 类型 | 组成 | 适用场景 | 注意 |
| --- | --- | --- | --- |
| 侧边导航布局 | `Aside` + `Content` | 导航层级较深、页面切换效率要求高 | 会压缩内容区横向空间 |
| 顶部导航布局 | `Header` + `Content` | 主要操作在内容区、页面导航切换效率要求不高 | 内容区常设为固定宽度以保证信息稳定 |
| 混合导航布局 | `Header` + `Aside` + `Content` | 信息架构复杂、对导航效率有要求的应用型网站 | 顶部承载重要功能时可固定顶部/底部；内容过高时可固定侧边区域 |

实现建议：

- Web React / Vue：应用壳优先使用 `Layout` / `Header` / `Aside` / `Content` / `Footer`，侧边导航优先使用官方 `Menu + Layout` 组合，顶部导航优先使用官方顶部导航 / `Menu.HeadMenu` 等价组合。
- 侧边导航与顶部导航一般不要在同一页面同时完整并存；如业务必须并存，全页只能保留一个 Logo + 系统名称品牌位。
- 与标准侧栏或顶部导航组合时，`Header` / `t-layout__header` 默认使用 `var(--td-comp-size-xxxl)` 高度；自定义时同时设置 `height`、`min-height` 和 `flex-shrink: 0`，避免被内部控件或 flex 布局压缩。
- Mobile / Miniprogram：不要复刻 Web 应用壳，按当前端优先选 `Navbar`、`TabBar`、`Tabs`、`SideBar`、`Row` / `Col`、`Grid`、`Cell` 等组件。
- 顶部导航适合横向空间更重要、导航层级较浅的页面。
- 侧边导航适合后台、控制台、系统管理等高频切换页面。
- 混合导航适合一级导航在顶部、二级及以下导航在侧边的信息架构。

## 栅格系统

| 项 | TDesign 规则 |
| --- | --- |
| 网格基数 | `8px` |
| 栅格组成 | 列 `column`、槽 `gutter`、安全边距 `margin` |
| 默认槽宽 | `16px` |
| 默认安全边距 | `24px`，可按实际情况使用 8 的倍数 |
| 内容区列数 | `12` 栅格 |
| 常见列结构 | `8`、`12`、`16`、`24` |

布局栅格类型：

| 类型 | 规则 |
| --- | --- |
| 无侧边栏布局栅格 | 内容区域占据页面全部宽度 |
| 定宽侧边栏展开 | 侧边栏在断点范围内固定，剩余空间给内容区；默认展开宽度 `232px` |
| 定宽侧边栏收起 | 默认收起宽度 `64px` |

侧边栏可做响应式布局：当浏览器宽度小于配置断点值时，侧边导航从展开态切换到收起态；TDesign 默认断点为 `992px`。

## 响应式断点

TDesign 基于不同显示设备设置 3 个断点，兼顾平板和 PC 设备。PC 断点未直接使用主流屏幕宽度，而是下调一定宽度，避免 Safari 等浏览器纵向滚动条出现/消失时导致断点附近布局抖动。

| 断点 | 断点值 | 响应区间 | 槽宽 | 栅格行为 | 设备参考 |
| --- | --- | --- | --- | --- | --- |
| `sm` | `768px` | `768px-991px` | `16px` | 内容区块根据断点堆叠或缩放 | 平板 |
| `md` | `992px` | `992px-1199px` | `16px` | 内容区块根据断点堆叠或缩放 | 超小尺寸电脑 |
| `lg` | `1200px` | `> 1200px` | `16px` | 大于断点值时始终保持水平排列 | 小尺寸电脑 |

## 栅格行为

| 行为 | 说明 | TDesign 规则 |
| --- | --- | --- |
| 固定栅格 | 固定列宽、固定槽宽、固定安全边距；内容宽度在特定断点范围内不变化 | 适合需要稳定阅读宽度或固定工作区的页面 |
| 流式栅格 | 流式列宽、固定槽宽、固定安全边距；内容宽度随浏览器变化 | 浏览器宽度大于最小断点 `768px` 时，内容区随浏览器增减 |

固定栅格最小宽度：

| 布局 | 最小宽度 | 行为 |
| --- | --- | --- |
| 无侧边栏 | `768px` | 小于最小断点后页面不再缩小，出现横向滚动条 |
| 侧边栏 | 内容区 `704px` | 页面最小宽度 `768px`，收起侧边栏 `64px`；内容区小于 `704px` 后出现横向滚动条 |

## 间距规则

- 页面布局中的内容元素应保持规律性间距。
- 默认遵循 `8px` 基数，例如 `8`、`16`、`24`、`32`、`40`、`48`。
- 可使用 `4px` 和 `12px` 作为更细粒度的小间距。
- Web 页面安全边距默认 `24px`；若业务调整，优先使用 8 的倍数。
- Web 中后台优先使用 TDesign `Space`、`Row`、`Col`、`Layout` 和组件自身 spacing props；Mobile / Miniprogram 按当前端布局组件能力实现，不要手写大量零散 `margin`。

## 组件映射

| 设计需求 | 优先组件或能力 |
| --- | --- |
| Web 应用壳 | `Layout`、`Header`、`Aside`、`Content`、`Footer` |
| 侧边导航 | `Menu + Layout` 侧栏组合 |
| 顶部导航 | 官方顶部导航 / `Menu.HeadMenu` 等价组合 |
| 内容区栅格 | `Row` / `Col` 或当前栈 Grid 能力 |
| 元素间距 | `Space`、组件布局 props、设计变量 |
| 卡片化内容区 | `Card` + 栅格布局 |
| 表单布局 | `Form` / `FormItem` 的布局能力，必要时配合 `Row` / `Col` |

## 禁止行为

- 禁止把 Web `Layout` 应用壳概念直接套到 Mobile 或 Miniprogram。
- 禁止忽略 `8px` 栅格基数，随意写 `margin: 13px`、`gap: 17px` 等无规律间距。
- 禁止在 Web 侧边栏布局中不考虑 `232px` 展开、`64px` 收起和 `992px` 响应断点。
- 禁止侧栏和顶栏各放一套 Logo / 系统名称。
- 禁止把 `Header` / `t-layout__header` 改成非组件尺寸阶梯值，或只写 `height` 导致被 flex 布局压缩。
- 禁止在内容区手写大段 flex/grid 样式复刻当前端 TDesign `Layout`、`Row`、`Col`、`Space` 已有能力。
- 禁止为了填满屏幕牺牲固定宽度内容区的可读性和信息稳定性。
