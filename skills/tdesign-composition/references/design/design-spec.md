# TDesign 对话式设计规范

本文用于纯对话式页面生成、页面改造和视觉走查。目标是让 AI 在没有 Figma 交付稿时，也能按 TDesign 的中后台设计语言生成稳定、清晰、可维护的界面。

## 适用范围

- 适用：Web 中后台、控制台、运营后台、配置页、数据列表、表单录入、详情页和仪表盘页面。
- 适用：用户要求“按 TDesign 风格”“优化页面视觉”“生成后台页”“对齐设计规范”但未提供具体设计稿。
- 不适用：像素级还原、Figma 组件实例选择、设计交付审核、品牌视觉创作或非 TDesign 项目。

## 设计目标

- 现代简约、专业中性、高效清晰，多端统一但不跨端照搬。
- 优先使用 TDesign 组件、组件 props、布局组件和 Design Token，少写自定义 CSS。
- 页面视觉服务于信息层级、操作效率和可读性，不为了装饰增加复杂图形。
- 状态表达必须清楚，不能只靠颜色；错误、告警、成功和品牌语义不可互换。

## 生成流程

1. 先确认平台和技术栈，避免混用 Web、Mobile、Miniprogram、React、Vue 3 和 Vue 2 写法。
2. 先定页面结构，再定组件组合，最后补最小样式。
3. Web 中后台优先用 `Layout`、`Menu`、`Header`、`Aside`、`Content`、`Breadcrumb`、`Card`、`Form`、`Table`、`Pagination`、`Dialog`、`Drawer` 等组件组织页面。
4. 涉及具体组件 props、事件、插槽和类型时，必须回到当前技术栈 API skill，不凭经验编造。
5. 需要图标时先用 `tdesign-icons` 查询图标名，再按当前技术栈写法使用图标组件。

## 页面结构

- 后台应用壳优先使用 `Layout` 加导航组件，不用裸 `div` 从零拼整套导航。
- 侧边导航适合层级深、切换频繁的管理系统；顶部导航适合一级模块少、横向空间优先的页面。
- 内容区优先采用卡片、区块和栅格组织，避免整页信息没有分组。
- 页面主操作保持唯一，次要操作降级为普通按钮、链接、下拉菜单或更多操作。
- 危险操作必须有二次确认，优先使用 `Popconfirm`、`Dialog` 或当前栈等价组件。

## 视觉层级

- 页面背景、卡片背景、分割线和文字颜色使用 TDesign 语义 Token，不直接写零散 hex。
- 标题、正文、辅助信息、占位说明和禁用态要有明确层级，避免所有文案同色同粗细。
- 表单项、表格列、操作区和卡片标题保持左对齐；金额、数量等数值列可右对齐。
- 空状态、加载态、错误态和无权限态必须明确，不留空白页面。
- 弹窗、抽屉和通知承载临时任务，不应替代主页面长期信息架构。

## 间距与密度

- 页面外边距、区块间距和组件间距优先使用 `--td-size-*` 或 TDesign 组件自带 spacing 能力。
- Web 中后台内容区常用 24px 水平安全边距，区块间距优先 16px、24px、32px。
- 表单、表格和筛选区以可读性优先，不为紧凑牺牲点击区域和行高。
- 同一页面内圆角、阴影和边框层级保持统一，不混用过大圆角与直角风格。

## 颜色与状态

- 品牌色用于主操作、选中态、链接倾向和重点强调。
- 错误色只表达失败、危险、删除或阻断问题；告警色表达风险提醒；成功色表达完成或通过。
- 自定义彩色实心底上的文字、图标和头像缩写，必须使用 `color: var(--td-text-color-anti)`。
- 给 `Avatar` 设置自定义 `background` 时，必须同步设置反色文字，或提供统一的 `.t-avatar` 兜底样式。
- 图表、多分类和装饰色不应滥用功能色，优先使用项目图表规范或扩展色体系。

## 图标与插图

- TDesign 项目中的常规 UI 图标必须使用 TDesign Icons，不用 Emoji、自绘 SVG、外部 iconfont 或临时网络图片占位。
- 图标颜色默认继承文本颜色，必要时使用 `--td-text-color-primary`、`--td-text-color-secondary` 或 `--td-brand-color`。
- 按钮前缀、菜单项、状态提示和空状态图标要服务语义，不为每个文字项强行配图标。

## 禁止行为

- 禁止在 TDesign 已有组件时手写等价控件，例如手写弹窗、分页、表格、菜单和表单校验。
- 禁止大量硬编码颜色、字号、间距、圆角和阴影。
- 禁止同时引入第二套组件库或第二套设计语言，除非 TDesign 明确不满足且用户同意。
- 禁止用装饰性渐变、大面积高饱和背景或复杂阴影破坏中后台专业感。
- 禁止只根据组件名猜 API，必须按当前技术栈资料确认真实写法。

## 交付前自检

- 页面是否优先使用 TDesign 组件和布局能力。
- 颜色、文字、边框、背景、间距和圆角是否优先使用 Token。
- 主次操作、危险操作和状态反馈是否清晰。
- 表单、表格、弹窗、抽屉、空状态和加载态是否覆盖关键场景。
- 图标名是否来自 TDesign Icons，并符合当前技术栈写法。
