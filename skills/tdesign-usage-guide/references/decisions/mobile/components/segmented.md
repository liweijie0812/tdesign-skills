# Mobile Segmented 何时使用

本文描述 `tdesign-mobile-react`、`tdesign-mobile-vue`、`tdesign-miniprogram` 和 `tdesign-uniapp` 中 `Segmented` 的设计选型。具体 props、事件、插槽、external classes 和平台能力必须回到当前栈 API 确认。

## 何时使用

- 用于同一区域内少量平级视图、状态或范围的快速切换。
- 适合二到四个轻量选项，不适合承载应用主导航。
- 主功能模块切换优先使用 `TabBar`，页面内内容分类优先使用 `Tabs`。

## 选型要点

- 选项应少且含义短，适合“全部/未读”“日/周/月”“列表/卡片”等轻量切换。
- 切换范围通常只影响当前小区域或当前列表，不应改变应用主模块。
- 若分类较多、需要横向滚动或承载独立内容面板，使用 `Tabs`。
- 若选项是表单值并需要提交，优先确认 `Radio`、`Picker` 或表单控件是否更合适。

## 反模式

- 不要用 `Segmented` 承担应用主导航或复杂分类导航。
- 不要放入过长文案或过多选项，移动端会增加误触和阅读成本。
- 不要用它替代表单单选控件，除非语义确实是视图/状态切换。
- 不要直接套用 Web 分段控件的密度和宽度。
