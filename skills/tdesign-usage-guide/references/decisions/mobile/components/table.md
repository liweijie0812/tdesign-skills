# Mobile Table 何时使用

本文描述 `tdesign-mobile-react`、`tdesign-mobile-vue`、`tdesign-miniprogram` 和 `tdesign-uniapp` 中 `Table` 的设计选型。具体 `columns`、`data`、`rowKey`、`height`、`maxHeight`、`loading`、固定行列、合并单元格、事件和小程序/UniApp 支持情况必须回到当前栈 API 确认。

## 何时使用

- 仅在移动端确实需要展示少列、低密度、结构化数据时使用。
- 适合账单明细、参数对比、轻量报表、规格信息等需要字段对齐的场景。
- 如果主要任务是浏览条目流、消息、订单或资源列表，优先使用 `List`、`Cell` / `CellGroup`。
- 如果用户需要查看单条记录详情，优先进入详情页或使用信息分组，不要强行塞进表格。

## 移动端约束

- 控制列数和字段密度，优先保留核心字段，次要字段进入详情页。
- 宽表、复杂多列表头、批量编辑和大量操作列不适合直接在移动端使用。
- 需要横向滚动时必须保证用户知道可滚动，并避免关键字段被隐藏。
- 表格高度、固定行列和滚动容器要与页面滚动、吸底按钮、安全区协调。

## 替代方案

- 单列信息流用 `List` 或 `Cell` / `CellGroup`。
- 对象详情用详情页、`CellGroup` 或卡片分组。
- 多字段编辑用 `Form`，不要在移动端表格中做复杂行内编辑。
- 分类切换用 `Tabs` / `Segmented`，筛选排序用 `Search`、`DropdownMenu`、`Picker` 或筛选面板。

## 状态与反馈

- 加载中使用 `loading`、`Skeleton` 或页面加载反馈，不要展示空白表格。
- 无数据时使用 `Empty`，并提供重试、重置筛选或创建入口。
- 单元格内容过长应截断、换行或进入详情，不要破坏整体触控和阅读。
- 表格行可点击时应给出明确反馈，并避免与横向滚动、复制文本等操作冲突。

## 反模式

- 不要照搬 Web 宽表、固定多列、复杂筛选和密集操作列。
- 不要用 `Table` 承载商品列表、消息流、审批流等单列浏览任务。
- 不要在小屏里强行做批量编辑、列配置和复杂拖拽。
- 不要忽略小程序/UniApp 当前栈能力差异，复杂列能力必须查 API。
