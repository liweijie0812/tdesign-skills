# Mobile Switch 何时使用

本文描述 `tdesign-mobile-react`、`tdesign-mobile-vue`、`tdesign-miniprogram` 和 `tdesign-uniapp` 中 `Switch` 的设计选型。具体 props、事件、插槽、external classes 和平台能力必须回到当前栈 API 确认。

## 何时使用

- 用于即时生效的开关状态。
- 如果值需要随表单提交或用户最终确认后生效，优先使用 `Checkbox` 或表单控件。
- 适合开启通知、启用服务、允许权限、显示/隐藏等二元状态切换。
- 常与 `Cell` 或设置项组合，用户点击后状态立即改变。

## 选型要点

- 状态文案和上下文应让用户理解当前是开启还是关闭，以及切换后的影响。
- 高风险开关需要确认、权限校验或失败回滚，不应误触后不可逆。
- 异步切换时需要加载、禁用或错误反馈，避免连续点击造成状态错乱。
- 小程序原生权限或系统开关能力必须按当前平台 API 确认，不从 TDesign 设计规则推断。

## 反模式

- 不要用 `Switch` 表达随表单提交才生效的选项。
- 不要用 `Switch` 作为多选或单选控件。
- 不要把危险操作做成无确认的即时开关。
- 不要手写开关样式重复实现 TDesign Switch。
