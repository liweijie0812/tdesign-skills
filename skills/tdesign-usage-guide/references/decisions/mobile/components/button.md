# Mobile Button 何时使用

本文描述 `tdesign-mobile-react`、`tdesign-mobile-vue`、`tdesign-miniprogram` 和 `tdesign-uniapp` 中 `Button` 的设计选型。具体 `theme`、`variant`、`shape`、`size`、`block`、`loading`、`loadingProps` / `loading-props`、`open-type`、事件、插槽和 external classes 必须回到当前栈 API 确认。

## 何时使用

- 当前流程结束或新流程开启需要用户点击触发时使用，例如提交、保存、确认、删除、登录、支付、授权、上传。
- 表单或长页面中的主操作常需要固定在底部、顶部或安全区内，保证用户滚动后仍能完成任务。
- 当点击结果是跳转、协议、页脚链接或轻量文本入口时，优先使用 `Link`。
- 当操作是全局高频或强引导入口并需要浮在内容上时，才考虑 `Fab`。

## 优先级

- `primary` 语义用于当前页面最重要的主动作，同一区域不应出现多个主按钮。
- `default` 或低强调按钮用于取消、返回、稍后处理、预览等次要动作。
- `danger` 用于删除、移除、注销、取消订单、关闭服务等高后果动作，通常需要 `Dialog` 二次确认。
- `light` 适合低强调品牌色动作或辅助入口，不应替代主按钮。
- 文字或虚线形态适合轻量、辅助或新增类动作，不能承载关键确认。

## 移动端形态

- `block` 适合移动端单列布局、表单底部、结果页和固定操作区中的主按钮。
- 吸底按钮要避开 `TabBar`、安全区、键盘和滚动容器，不要遮挡内容或列表最后一项。
- 图标按钮可用于扫码、定位、清空、搜索、选择等辅助动作；陌生或高风险动作必须搭配文字。
- 圆形、方形或仅图标按钮应保证触控面积，不能只追求视觉紧凑。
- 多个按钮并排时应控制数量，复杂操作集合优先使用 `ActionSheet`。

## 状态与平台能力

- `loading` 用于提交、支付、登录、上传等异步动作，并防止重复点击。
- `disabled` 用于动作暂不可用，应通过说明文案、表单错误或状态提示解释原因。
- 小程序和 UniApp 的开放能力按钮必须按当前栈 API 使用 `open-type` 及对应事件，不要用普通点击事件模拟授权、手机号、分享、客服等平台能力。
- 使用手机号、隐私授权、分享等平台能力后，应按平台要求处理失败、取消、额度限制和重复触发。

## 组合规则

- 表单页常用“固定主按钮 + 次要文字入口”，长表单可分步或分组，不要在底部堆叠过多按钮。
- 结果页用 `Result + Button + Link` 表达下一步，主按钮负责继续流程，链接承载辅助跳转。
- 列表项操作优先使用 `SwipeCell` 或进入详情页处理，高风险动作需要确认。
- 操作集合优先使用 `ActionSheet`；复杂筛选或编辑流程使用 `Popup` / `Drawer` 承载表单。

## 反模式

- 不要在同一区域放多个主按钮，让用户无法判断下一步。
- 不要用 `Button` 替代页面主导航，主模块切换使用 `TabBar`，页面内分类使用 `Tabs` / `SideBar`。
- 不要把 Web 的 hover、右键、密集工具栏和多列按钮组照搬到移动端。
- 不要只用图标表达删除、支付、授权等关键动作。
- 不要把其他组件库的按钮类型、颜色和变体命名直接套到 TDesign Mobile；必须按当前栈 API 使用 TDesign 的 `theme`、`variant`、`shape` 等能力。
