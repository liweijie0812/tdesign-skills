# Web TreeSelect 何时使用

本文描述 Web 场景下 `TreeSelect` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 当用户需要在紧凑表单控件中从树形数据里选择一个或多个项时使用。
- 当用户需要直接浏览、展开并操作层级结构时，优先使用 `Tree`。
- 适合组织、部门、分类、权限节点等树形数据作为表单值或筛选条件的场景。
- 当选择结果需要像普通字段一样回显在输入区域时使用。

## 选型要点

- 先判断用户是否需要选择树节点，而不是浏览或管理整棵树。
- 路径式逐级收窄选择优先 `Cascader`；完整树浏览、拖拽、节点操作优先 `Tree`。
- 多选时要确认父子节点勾选关系、半选状态、回显方式和搜索能力。
- 树数据量大时要关注加载、搜索和性能能力，具体实现必须查当前栈 API。

## 反模式

- 不要用 `TreeSelect` 替代完整树管理界面。
- 不要把扁平选项强行做成树选择，普通枚举使用 `Select`。
- 不要忽略多选父子关系，导致提交值和用户预期不一致。
- 不要把 Mobile TreeSelect 的交互密度和展示方式直接套用到 Web。
