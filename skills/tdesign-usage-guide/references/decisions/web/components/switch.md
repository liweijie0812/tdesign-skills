# Web Switch 何时使用

本文描述 Web 场景下 `Switch` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于即时生效的开关状态切换。
- 如果值需要随表单一起提交，而不是即时生效，应优先使用 `Checkbox`。
- 适合启用/停用、开启/关闭、允许/禁止等二元状态。
- 状态变化会立即影响系统、配置或用户可见行为时使用。

## 选型要点

- 切换前后状态应清晰，文案要表达当前状态或结果，而不是模糊动作。
- 高风险切换需要确认、权限校验或撤销机制，不应点击即不可逆。
- 异步切换时要处理加载、失败回滚和错误反馈。
- 表单内“是否选择某附加项”且只在提交后生效时，优先 `Checkbox`。

## 反模式

- 不要用 `Switch` 表达多选、单选或不立即生效的表单值。
- 不要把危险操作做成无确认的开关。
- 不要只用颜色表达状态，必须有清晰标签或上下文。
- 不要手写开关样式重复实现 TDesign Switch。
