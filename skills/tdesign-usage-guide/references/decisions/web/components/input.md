# Web Input 何时使用

本文描述 Web 场景下 `Input` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于短文本自由输入。
- 需要反馈校验状态时，可搭配状态和提示文本。
- 多行文本使用 `Textarea`。
- 搜索是主要任务时，优先使用 `Input` 的搜索类型、图标、后置按钮或项目已有的 TDesign 搜索封装，不要编造不存在的组件。

## 选型要点

- 输入内容应是短值或单行文本，例如名称、账号、手机号、邮箱、编号、关键词。
- 值需要随一组字段提交或校验时，通常放入 `Form`，并在字段附近展示校验反馈。
- 需要候选建议但仍允许自由输入时使用 `AutoComplete`；必须从固定选项选择时使用 `Select`。
- 需要输入数字时优先使用 `InputNumber`；多行备注、说明或评论使用 `Textarea`。

## 相关取舍

- 相似组件取舍见 `../similar-components.md`，优先按当前平台和当前技术栈确认。
- 常见相关组件：`Textarea`、`AutoComplete`、`InputNumber`、`Form`。

## 反模式

- 不要用 `Input` 模拟下拉选择、层级选择或日期时间选择。
- 不要只在 placeholder 中放关键规则；校验、格式和限制应有可见说明或反馈。
- 不要用普通文本输入承担高风险命令确认，必要时结合 `Dialog` 或明确确认流程。
- 不要把 Mobile 或其他技术栈的事件、插槽和样式写法直接套用到 Web。
