# Web SelectInput 何时使用

本文描述 Web 场景下 `SelectInput` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于构建自定义选择类组件时，承担输入框展示、标签展示、清除、聚焦和弹层触发等底层能力。
- 适合标准 `Select` 无法表达的复杂选择器，例如自定义候选面板、复合筛选值、业务封装选择器。
- 标准单选、多选、可搜索选项选择优先使用 `Select`。
- 层级路径选择优先使用 `Cascader` 或 `TreeSelect`，不要只因为视觉像输入框就使用 `SelectInput`。

## 选型要点

- 先确认 `Select`、`Cascader`、`TreeSelect`、`AutoComplete` 是否能直接满足需求。
- 使用它时通常意味着项目要封装一个更高层选择器，需要同时设计候选展示、键盘交互、清除和校验语义。
- 只负责底层输入展示和触发能力，具体值结构、选项列表和弹层内容由上层业务组件承担。

## 反模式

- 不要用 `SelectInput` 重做普通下拉选择。
- 不要把它当成 `Input` 的样式替代品。
- 不要绕开 `Select` 已有的多选、搜索、清除和标签展示能力。
- 不要把其他技术栈的事件、插槽和类型写法直接套用到当前 Web 栈。
