# Web Button 何时使用

本文只描述 Web 场景下 `Button` 的选型和设计规则。具体 `theme`、`variant`、`shape`、`size`、`loading`、`disabled`、`block`、`href`、`tag`、事件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 当用户需要点击操作命令并触发业务逻辑时使用，例如提交、保存、删除、导出、刷新、启动任务。
- 当点击结果是修改数据、提交命令或启动流程时，优先使用 `Button`。
- 当点击结果是跳转到页面、区域、文件或外部资源时，优先使用 `Link`；如果确实需要按钮视觉并使用跳转能力，必须按当前栈 API 确认 `href` / `tag` 行为。

## 优先级

- 主按钮用于页面或操作区域中最重要的动作，一个操作区域通常只保留一个主按钮。
- 次级按钮用于取消、返回、预览、保存草稿等低于主动作的操作。
- 文字按钮适合低强调、行内或表格操作；虚线按钮常用于新增、添加项等轻量动作。
- 危险按钮用于删除、移除、停用、重置、权限变更等高后果操作，应搭配二次确认或明确后果文案。
- 成功、警告等语义按钮只在结果或状态语义明确时使用，不要用颜色制造无意义强调。

## 状态与形态

- `loading` 用于异步提交、导出、保存等等待反馈场景，并防止重复点击。
- `disabled` 用于动作暂不可用，应在附近说明原因；不要用禁用态隐藏业务规则。
- 图标按钮用于空间紧凑或高频熟悉操作，含义不通用时必须搭配文字或 `Tooltip`。
- 圆形、方形或仅图标按钮只适合紧凑操作入口，不适合承载陌生或高风险动作。
- `block` 适合容器内需要占满宽度的单一主操作，不适合表格行操作或密集工具栏。
- `ghost` 适合有色或图片背景上的按钮，不应在普通白底页面中滥用。

## 组合规则

- 表单底部常用“主操作 + 次操作”，例如提交 + 取消；按钮顺序应符合当前产品规范。
- 操作超过 3 个时，优先展示高频操作，其余收纳到 `Dropdown`。
- 表格操作列优先使用文字按钮或链接式操作，低频和危险操作可收纳并配合 `Popconfirm` / `Dialog`。
- 页面顶部或区块头部的主操作应与标题、筛选和批量操作保持清晰层级，不要堆叠多个强按钮。

## 反模式

- 不要在同一操作区域放多个主按钮争抢焦点。
- 不要用 `Button` 承担导航菜单，导航结构优先使用 `Menu`、`Breadcrumb`、`Tabs` 或 `Link`。
- 不要只用颜色区分危险操作，应通过文案、确认和反馈表达后果。
- 不要用自定义 `div`、`span` 或图标重复实现 TDesign Button 已有能力。
- 不要把其他组件库的按钮类型、颜色和变体命名直接套到 TDesign；必须按当前栈 API 使用 TDesign 的 `theme`、`variant` 等能力。
