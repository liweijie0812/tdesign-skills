# Web Card 何时使用

本文描述 Web 场景下 `Card` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于将相关内容和操作组织在一个容器中。
- 适合仪表盘区块、预览、内容模块或对象摘要。
- 当页面中存在多个独立信息单元，需要通过边界、标题和操作区表达分组时使用。
- 适合承载统计摘要、对象预览、配置分组、推荐内容或列表中的富内容项。

## 选型要点

- 卡片应围绕一个明确主题组织内容，标题、主体和操作要服务同一对象或模块。
- 数据是行列结构且需要对比、排序、筛选或批量操作时使用 `Table`，不要用卡片网格模拟表格。
- 只读键值详情优先使用 `Descriptions`；连续条目流优先使用 `List`。
- 多卡片布局要控制密度和对齐，避免把页面切成大量无语义容器。

## 反模式

- 不要只为了加边框或阴影就使用 `Card`，先判断是否存在独立信息单元。
- 不要在卡片中塞入过多无关操作，复杂任务应拆成页面、表单或抽屉。
- 不要用 `Card` 替代表格、详情描述或列表组件的语义。
- 不要手写容器样式重复实现 TDesign Card 已有能力。
