# Web Dropdown 何时使用

本文描述 Web 场景下 `Dropdown` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于将上下文相关操作收纳在触发器后面，节省空间。
- 适合操作菜单，不适合承担值选择。
- 当用户需要从选项中选择值时，优先使用 `Select`。
- 适合表格行操作、按钮旁更多操作、头像菜单、工具栏次级命令等场景。

## 选型要点

- 菜单项应是可执行动作或跳转，不应是表单字段值。
- 高频主动作应直接暴露为 `Button`，低频、次级或上下文操作再收纳进 `Dropdown`。
- 危险操作可放入 `Dropdown`，但需要 `Popconfirm` / `Dialog` 等确认机制时不要省略。
- 需要持续展示导航结构时使用 `Menu`，不要用 `Dropdown` 承担大型导航。

## 反模式

- 不要把 `Dropdown` 当成 `Select`、`Cascader` 或筛选表单使用。
- 不要隐藏唯一或最高频主操作，导致用户必须打开菜单才能完成核心任务。
- 不要在菜单中混合无关命令、导航和状态展示。
- 不要把 Mobile `ActionSheet` 或 `DropdownMenu` 的用法直接套到 Web。
