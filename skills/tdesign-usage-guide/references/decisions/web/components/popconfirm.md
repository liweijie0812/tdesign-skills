# Web Popconfirm 何时使用

本文描述 Web 场景下 `Popconfirm` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于靠近触发操作的轻量二次确认。
- 适合不需要强中断的确认场景。
- 严重、复杂或需要高度注意的后果应使用 `Dialog`。
- 常见于表格行删除、移除成员、取消关联、停用轻量配置等上下文明确的操作。

## 选型要点

- 触发点附近必须已经说明操作对象，确认文案只补充后果和确认动作。
- 适合一句话能说明后果的操作；需要展示详情、输入内容或多步骤决策时使用 `Dialog`。
- 对不可逆、高价值或批量危险操作，应升级为 `Dialog` 并提供更明确的风险说明。
- 异步确认时要有加载或禁用反馈，避免重复提交。

## 反模式

- 不要用 `Popconfirm` 承载长文本、表单、多个选项或复杂风险解释。
- 不要对所有普通操作都加确认，避免确认疲劳。
- 不要只用红色文案表达风险，应明确说明操作对象和后果。
- 不要用 `window.confirm()` 重复实现 TDesign 已有确认能力。
