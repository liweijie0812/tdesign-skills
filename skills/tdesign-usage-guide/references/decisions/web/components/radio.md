# Web Radio 何时使用

本文描述 Web 场景下 `Radio` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 当用户必须从少量选项中选择一个时使用。
- 选项较多或空间有限时，优先使用 `Select`。
- 适合性别、状态、类型、是否、展示模式等少量互斥选项。
- 当选项需要全部可见以便比较时，优先使用 `Radio` 而不是下拉。
- 按钮形式的单选框适合需要更明显突出选项、强化选择感或承载短标签选项的场景。

## 选型要点

- 选项必须互斥，用户同一时间只能选择一个值。
- 选项文案应短且可比较，过长说明可放到辅助文本或改用其他结构。
- 默认值要谨慎，涉及高风险或偏好选择时不要替用户默认选择。
- 选项数量较多、动态加载或需要搜索时使用 `Select`。
- 按钮形式适合少量高频选项、视图模式切换或状态切换；具体形态能力必须回到当前技术栈 API 确认。

## 反模式

- 不要用 `Radio` 表达多选，使用 `Checkbox`。
- 不要用 `Radio` 表达即时开关状态，使用 `Switch`。
- 不要把大量选项平铺成 Radio 造成页面拥挤。
- 不要手写圆点选择器重复实现 TDesign Radio。
