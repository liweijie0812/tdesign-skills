# Web Form 何时使用

本文描述 Web 场景下 `Form` 的设计选型。具体 `layout`、`labelAlign`、`labelWidth`、`rules`、`readOnly`、`disabled`、`scrollToFirstError`、`FormItem`、`FormList`、提交和校验方法必须回到当前技术栈 API 确认。

## 何时使用

- 当需要向用户收集、校验并提交一组信息时使用。
- 字段之间存在业务关系、校验规则、提交状态或统一禁用/只读控制时使用。
- 表单项需要与 `Input`、`Select`、`DatePicker`、`Upload`、`Checkbox`、`Radio`、`Switch` 等输入组件组合时使用。
- 如果只是展示只读事实，优先使用 `Descriptions`；如果只编辑单个值，可以使用对应输入组件而不必包装成完整表单。

## 布局规则

- 字段有明确逻辑顺序、内容较复杂或需要错误提示时，优先使用纵向布局。
- 筛选区、工具栏或少量短字段可使用行内布局，但不要把复杂编辑表单做成密集横排。
- 标签宽度应保证对齐和可读性，长标签优先换行或调整为顶部对齐。
- 表单区块多时应分组、分步或拆页面，不要把所有字段堆进单一长表单。

## 校验与反馈

- 必填、格式、长度、范围、异步校验等规则应放入 `Form` / `FormItem` 的校验体系，不要手写零散错误文本。
- 提交失败时应定位到第一个错误字段，必要时使用滚动到错误能力。
- 错误文案应说明如何修正，不只写“错误”或“无效”。
- 警告与错误要区分：警告可以允许继续，错误应阻止提交。

## 状态与提交

- 提交时配合 `Button` 的 `loading` 状态，避免重复提交。
- `disabled` 用于暂不可编辑，`readOnly` 用于可读不可改；不要用禁用态伪装详情页。
- 重置应明确是清空还是恢复初始值，避免误删用户输入。
- 表单外按钮触发表单提交时，必须按当前栈 API 确认 `form` / 实例方法能力。

## 与 JSON Schema

- 固定业务字段优先直接使用 TDesign `Form`。
- 字段来自后端配置、低代码平台或租户配置时，可以使用项目级 schema 渲染器，但它不是 TDesign 官方 `Form` API。
- Schema 渲染器可以内部映射到 TDesign `Form` 和输入组件，但不能编造 `SchemaForm`、`JsonSchemaForm` 等官方组件名。

## 反模式

- 不要绕过 `FormItem` 自行拼装标签、错误文案和校验状态。
- 不要把大型复杂表单塞进 `Dialog`，除非业务必须强中断。
- 不要在一个表单中混合过多无关任务；应拆分为分组、步骤或独立页面。
- 不要把 Web 表单布局直接套到移动端。
