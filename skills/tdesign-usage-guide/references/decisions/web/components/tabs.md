# Web Tabs 何时使用

本文描述 Web 场景下 `Tabs` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于在同一上下文内切换平级内容面板。
- 不适合表达有先后顺序的流程，流程类场景优先使用 `Steps`。
- 适合同一对象、同一页面或同一模块下的分类信息切换，例如概览、配置、日志、成员。
- 当切换会改变应用主导航位置或跨模块跳转时，优先使用 `Menu` 或路由导航。

## 选型要点

- Tab 项应平级且互斥，不表达父子关系、流程顺序或操作集合。
- Tab 数量应控制在用户能快速识别的范围内；过多分类应考虑 `Menu`、筛选或信息架构调整。
- 内容切换成本较高时，应保留当前状态、加载反馈和空状态，不要让用户误以为页面跳转失败。
- 需要深层页面路径和返回层级时，搭配 `Breadcrumb` 或路由，不要只靠 Tabs 表达位置。

## 相关取舍

- 相似组件取舍见 `../similar-components.md`，优先按当前平台和当前技术栈确认。
- 常见相关组件：`Menu`、`Breadcrumb`、`Steps`。

## 反模式

- 不要用 `Tabs` 表达分步流程，流程进度使用 `Steps`。
- 不要用 `Tabs` 承担应用主导航或复杂树形导航。
- 不要把筛选条件伪装成 Tabs；多条件筛选应使用表单或筛选组件。
- 不要把 Mobile TabBar / Tabs 的触控布局直接套用到 Web。
