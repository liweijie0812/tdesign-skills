# Web Alert 何时使用

本文描述 Web 场景下 `Alert` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于页面级或区块级的提示、成功、警告或错误信息。
- 当信息需要在上下文中持续可见时使用。
- 适合表单规则说明、权限限制、风险提示、系统状态、配置前置条件或页面级异常说明。
- 操作后短暂反馈优先使用 `Message`；更完整的全局通知使用 `Notification`。

## 选型要点

- 信息应与所在页面或区块强相关，用户需要在操作过程中持续看到。
- 文案要直接说明状态、原因和下一步，不只写“提示”或“错误”。
- 可关闭 Alert 只适合非关键提示；关键风险、合规说明或阻断条件不应被轻易关闭。
- 多条同类提示应合并或分组，不要堆叠多个 Alert 干扰主要任务。

## 反模式

- 不要用 `Alert` 代替字段级校验，字段错误应靠近字段展示。
- 不要把一次性操作成功提示做成长期 Alert，优先使用 `Message`。
- 不要用纯样式块手写提示条，先使用 TDesign Alert。
- 不要把移动端 `NoticeBar` 的公告用法直接套到 Web Alert。
