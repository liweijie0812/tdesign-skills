# Web Descriptions 何时使用

本文描述 Web 场景下 `Descriptions` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于只读字段和值的信息展示。
- 适合详情页、摘要页、确认页。
- 需要用户编辑或提交时，使用 `Form`。

## 选型要点

- 字段应以标签和值为主，用户任务是阅读、核对或确认信息。
- 信息较多时按业务分组，避免一长串字段降低可读性。
- 需要编辑、校验或提交时使用 `Form`；需要横向比较多条记录时使用 `Table`。
- 可承载状态、标签、链接等展示内容，但不应变成复杂操作区。

## 反模式

- 不要用 `Descriptions` 模拟表单编辑，编辑态应切换到 `Form`。
- 不要用表格模拟只读详情字段，优先 `Descriptions`。
- 不要把无关字段堆在同一个描述组中，应按业务语义分组。
- 不要为视觉排版手写键值布局重复实现 TDesign Descriptions。
