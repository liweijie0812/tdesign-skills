# Web Skeleton 何时使用

本文描述 Web 场景下 `Skeleton` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于内容结构已知但数据尚未返回时的占位展示。
- 适合首屏列表、卡片、详情页、摘要区块、表格轮廓等用户能预期布局的场景。
- 当等待时间可能超过瞬时反馈，且空白页面会造成不确定感时使用。
- 如果只是按钮提交、导出或无法预判内容结构，优先使用 `Loading`。

## 选型要点

- 骨架形状应接近真实内容结构，但不需要逐像素还原。
- 首屏可用骨架稳定页面高度，减少数据返回后的布局跳动。
- 数据返回为空时切换到 `Empty`，返回失败时切换到错误状态，不要一直保留骨架。

## 反模式

- 不要在内容结构未知、变化很大或加载极短的场景强行使用 Skeleton。
- 不要用复杂骨架复刻完整页面视觉，避免维护成本高于收益。
- 不要把 Skeleton 当作空状态、错误状态或权限状态。
- 不要手写灰块和动画重复实现 TDesign 已有能力。
