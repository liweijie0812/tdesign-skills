# Web Loading 何时使用

本文描述 Web 场景下 `Loading` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于用户触发操作后，系统正在等待结果但无法展示结构化占位的场景。
- 适合按钮提交、局部卡片刷新、表格区域刷新、整页初始化等通用等待状态。
- 当最终内容结构已知，尤其是列表、卡片、详情、表格骨架明确时，优先使用 `Skeleton` 降低等待感。
- 当进度可量化且需要展示完成比例时，使用 `Progress`，不要用转圈代替真实进度。

## 选型要点

- 等待范围要与加载范围一致：按钮动作使用按钮加载态，区块刷新使用区块内加载，整页阻塞才使用页面级加载。
- 加载文案应说明正在发生什么，例如“保存中”“导出中”“加载数据中”，不要只给无上下文转圈。
- 异步操作完成后应回到 `Message`、`Notification`、`Alert` 或页面状态表达结果。

## 相关取舍

- 相似组件取舍见 `../similar-components.md`，优先按当前平台和当前技术栈确认。
- 常见相关组件：`Skeleton`、`Progress`、`Empty`。

## 反模式

- 不要在结构明确的首屏内容上只显示大面积空白 Loading。
- 不要用 Loading 掩盖错误、空数据或权限不足；这些应分别用错误提示、`Empty` 或业务状态表达。
- 不要为了自定义动画手写转圈或引入其他组件库；先使用 TDesign Loading 能力。
- 不要把 Mobile 或其他技术栈的 API、插槽和样式写法直接套用到 Web。
