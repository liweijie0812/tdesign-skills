# Web Cascader 何时使用

本文描述 Web 场景下 `Cascader` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于从层级数据中逐级选择，且下一级选项依赖上一级选项。
- 适合地区、组织、分类、权限路径等选择。
- 当用户需要在同一面板中查看更完整的树结构时，优先使用 `TreeSelect`。
- 当用户选择的是一条路径，并需要逐级收窄范围时使用 `Cascader`。

## 选型要点

- 数据必须有清晰父子路径，且用户的目标是选中一条或多条路径。
- 选项层级较深时，要关注搜索、懒加载、默认展开和回显能力，具体能力必须查当前栈 API。
- 如果用户需要比较同层大量节点、批量勾选或操作树节点，优先使用 `Tree` 或 `TreeSelect`。
- 如果只是扁平枚举、状态或类型选择，使用 `Select` 或 `Radio`。

## 反模式

- 不要把其他端或其他技术栈的 API、事件、插槽和样式写法直接套用到当前平台。
- 不要为了视觉接近而手写层级浮层，先使用 TDesign Cascader / TreeSelect / Tree。
- 当前组件不能满足需求时，先查相似组件和降级策略，不要直接引入其他组件库或手写临时结构。
- 不要把无层级关系的普通枚举做成 `Cascader`。
- 不要用 `Cascader` 替代需要直接浏览、展开、勾选或操作完整层级结构的 `Tree`。
