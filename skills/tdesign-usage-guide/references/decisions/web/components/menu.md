# Web Menu 何时使用

本文描述 Web 场景下 `Menu` 的设计选型。具体 props、事件、插槽、子组件和类型必须回到当前技术栈 API 确认。

## 何时使用

- 用于导航结构或一组相关命令集合。
- 当多个条目需要持续展示、分组或层级组织时使用。
- 少量上下文操作应优先使用 `Dropdown`。
- 适合应用侧边导航、顶部导航、工作台模块入口、文档目录或持续可见的功能分组。

## 选型要点

- 菜单项应代表稳定页面、模块、功能入口或命令集合，而不是一次性反馈或表单值。
- 层级不宜过深，超过两到三级通常需要重新整理信息架构或提供搜索。
- 与路由联动时，要保证当前项、展开项和面包屑表达一致。
- 只在当前页面内切换平级内容时使用 `Tabs`，不要升级为应用级 `Menu`。

## 反模式

- 不要用 `Menu` 承担表单选择、筛选条件或一次性操作菜单。
- 不要把少量上下文操作做成常驻菜单；优先 `Dropdown`。
- 不要为了视觉接近手写导航列表，先使用 TDesign Menu 能力。
- 不要把 Mobile `TabBar` 或 `SideBar` 的导航结论直接套用到 Web。
