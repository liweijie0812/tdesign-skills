# Web Dialog vs Drawer

按任务中断强度和内容体量选择，不按视觉偏好选择。适用于 `tdesign-react`、`tdesign-vue-next` 和 `tdesign-vue`。

## 选择 Dialog

- 当前任务必须被局部中断，用户需要先完成确认、告警、短表单或关键决策。
- 内容较短，主要是确认、提示、少量字段编辑或结果反馈。
- 操作有风险或不可逆，需要明确的确认按钮和结果导向文案。
- 需要用户聚焦在当前决策，不应继续浏览页面其他区域。

## 选择 Drawer

- 内容需要更多横向或纵向空间，例如详情、配置、编辑、辅助流程。
- 用户仍需要保留主页面上下文，例如从列表打开详情、编辑侧栏或筛选配置。
- 任务可以作为主页面的附属面板存在，不必强制阻断用户。

## 相关组件

- 轻量二次确认优先 `Popconfirm`。
- 完全自定义浮层且标准组件无法满足时才考虑 `Popup`。
- Dialog 通用语义见 `api/_shared/dialog/contract.md`，端差异按 `api/_shared/dialog/` 下的 Web 文档确认。

## 不要这样用

- 不要把大型复杂表单塞进 `Dialog`，除非业务必须强中断。
- 不要用 `Drawer` 承担高风险确认，破坏性动作优先 `Dialog` 或 `Popconfirm`。
- 不要为了“看起来高级”把简单二次确认做成抽屉。
