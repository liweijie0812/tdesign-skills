# Select vs Cascader

按选项数据结构和用户选择路径判断。

## 选择 Select

- 选项是扁平列表，用户只需要选择一个或多个值。
- 选项数量较多但不需要表达层级，使用搜索能力提升效率。
- 选项用于表单筛选、状态、类型、负责人、标签等常见字段。
- 下拉内容只是候选值，不承担操作菜单。

## 选择 Cascader

- 选项是层级数据，并且下一级依赖上一级。
- 用户选择的是一条路径，例如地区、组织、分类、权限路径。
- 选择过程需要逐级收窄范围，而不是直接浏览整棵树。

## 相关取舍

- 需要在紧凑控件中选择树节点时，优先 `TreeSelect`。
- 需要直接浏览、展开、勾选或操作完整层级结构时，优先 `Tree`。
- 操作收纳使用 `Dropdown`，不要用 `Select` 承担操作菜单。

## 不要这样用

- 不要把无层级关系的普通枚举做成 `Cascader`。
- 不要把动作项放进 `Select` 让用户“选择一个操作”。
- 不要为少量可见单选项强行使用 `Select`，少量互斥选项可用 `Radio`。
